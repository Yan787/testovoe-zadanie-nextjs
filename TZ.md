# ТЗ — Frontend Interview Trainer

Пользователь открывает каталог вопросов, фильтрует их по теме и сложности, читает вопрос и раскрывает ответ. После входа он может отметить вопрос пройденным и посмотреть прогресс. Администратор добавляет и редактирует вопросы.

**Стек** — Next.js с App Router, TypeScript и PostgreSQL. Для первой версии оставь Cache Components выключенными, чтобы на практике проверить знакомые `revalidate`, `generateStaticParams` и `revalidatePath`.

## 1. Публичные страницы

| Маршрут | Что сделать | Что отработаешь |
| --- | --- | --- |
| `/` | Статическая главная с описанием и ссылкой на каталог. | SSG, `layout.tsx`, `Link`, метаданные. |
| `/problems` | Серверный компонент читает список из БД. Фильтры по теме и сложности записываются в URL. Клиентское поле поиска показывает подсказки через `GET /api/problems/search?q=...`. | RSC, `searchParams`, CSR, Route Handler, debounce и отмена устаревшего запроса. |
| `/problems/[slug]` | Подготовь несколько вопросов при сборке через `generateStaticParams`. Задай `revalidate = 300`. Сервер выводит вопрос, клиентская кнопка раскрывает ответ. Для неизвестного `slug` верни 404 через `notFound()`. | Динамический маршрут, SSG, ISR, граница `'use client'` и гидратация. |

Для первого запуска хватит 10 вопросов в базе. Храни у вопроса `slug`, заголовок, тему, сложность, текст и ответ. Ответ можно передать кнопке через props. Она будет раскрывать его без отдельного запроса.

## 2. Личный кабинет

- **`/login`** — вход через библиотеку аутентификации. `proxy.ts` перенаправляет гостя с `/dashboard` на `/login`. Сервер отдельно проверяет сессию перед чтением или записью прогресса.
- **`/dashboard`** — сервер рендерит прогресс текущего пользователя по запросу. Имя и заголовок покажи сразу, а статистику вынеси в отдельный серверный компонент под `<Suspense>`. Добавь тестовую задержку в загрузку статистики, чтобы увидеть Streaming.
- **«Отметить пройденным»** — форма вызывает Server Action. Сервер берёт ID пользователя из сессии и сохраняет статус вопроса в БД. После перезагрузки отметка должна сохраниться.

## 3. Админка и обновление кеша

На `/admin/problems` добавь форму создания и редактирования вопроса. Server Action проверяет роль и данные формы, сохраняет запись и вызывает `revalidatePath('/problems')`. При редактировании существующего вопроса обновляй и кеш его страницы, например через `revalidatePath('/problems/two-sum')`.

Чтобы увидеть разницу между **ISR по интервалу** и **обновлением по событию**, проверь оба сценария отдельно. Сначала измени текст вопроса прямо в БД и дождись истечения интервала. Затем измени тот же вопрос через админку и проверь, что кеш обновляется без ожидания интервала.

## Как проверить проект

1. Запусти `next build`, затем `next start`. Проверь в выводе сборки, какие маршруты подготовлены заранее, а какие рендерятся по запросу.
2. Открой карточку вопроса. Начальный HTML содержит условие. После загрузки JavaScript кнопка раскрывает ответ без нового HTTP-запроса.
3. Быстро набери запрос в поиске. В Network видно, что запрос запускается после паузы во вводе, а устаревший запрос отменяется.
4. Открой личный кабинет. Сначала видна оболочка с заглушкой, затем появляется статистика. В двух разных аккаунтах отображается свой прогресс.
5. Отредактируй опубликованный вопрос через админку и проверь, что публичная страница показывает новую версию без пересборки проекта.

**После основной версии** добавь `loading.tsx`, `error.tsx`, `generateMetadata` для карточек и один сквозной тест. Для сравнения с Pages Router можно в отдельной ветке реализовать карточку через `getStaticPaths` и `getStaticProps`, а затем перенести её в `app/`.
